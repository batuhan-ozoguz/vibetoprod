# Detection spike — 2026-09-03

Goal: prove that a deterministic ruleset can infer a vibe-coded app's
production service needs from its repo, and find where it breaks — before
building anything else on top of it.

## Method

1. **Corpus**: 33 real, public, generator-verified repos ([corpus.json](corpus.json)):
   15 Lovable (`lovable-tagger` in package.json), 7 Bolt (`.bolt/config.json`),
   7 v0 (v0.dev sync READMEs), 4 Cursor. Verified fingerprints, not keyword guesses.
2. **Ruleset v0**: 37 rules seeded from the detection tables of AWS's
   `deploy-on-aws` agent plugin ([awslabs/agent-plugins](https://github.com/awslabs/agent-plugins),
   Apache-2.0 — see NOTICE).
3. **Test**: shallow-cloned every repo, ran the detector, then manually
   inspected each repo's manifests and env examples for anything the rules
   missed or false-positived.

## Results

Correct and encouraging:

- **Supabase detection is strong** — the Lovable default stack (db+auth+storage)
  was fully caught in 6/15 Lovable repos that use it.
- **No false services on pure client-side apps** — 8 repos correctly produced
  "hosting only". Not inventing needs is what makes the eventual cost estimate
  trustworthy.

Gaps found (all fixed in ruleset v1 + `tools/detect.mjs`):

| Gap | Example repo | Fix |
|---|---|---|
| `next-themes` triggered the Next.js rule (prefix matching) | almost every Vite repo | exact-name matching; hosting rules get `priority`, detector reports one primary |
| Firebase stack invisible | tailorpal (lost auth+db+storage) | `firebase` → auth, database, storage |
| Long-running backends invisible | MemeCoin-Roulette (express in `server/`) | express/fastify/koa/hono/nestjs → `server` need; all package.json files in tree are scanned |
| AI keys in `.env.example` ignored | ata-360 (3 provider keys) | new `env-key` signal type |
| Vercel AI SDK unrecognized | llm-dj-mcp (`ai`, `@ai-sdk/groq`) | `ai` + `@ai-sdk/` rules |
| Zero web3 rules | nouncil (wagmi+viem+ethers) | web3-rpc category |
| Cloudflare deploys recommended Vercel | compare-openrouter-models (`wrangler.toml`) | wrangler/file override, priority 100 |
| Non-JS backends invisible | Task_Management (Spring Boot `pom.xml`) | pom.xml / requirements.txt file rules |

Ruleset v1: **61 rules** ([rules/ruleset.json](../rules/ruleset.json)).
Detector semantics are locked by `tools/detect.test.mjs`.

## What this proves

The core mechanic works: same repo in, same plan out, with evidence per
signal. The miss list was finite and fixable in one pass — the ruleset
compounds with every repo it sees, which is the point.
